# iphonectl

Open-source, TapKit-inspired control of a **real iPhone from your Mac** over USB — two
independent backends, one Claude Code skill, and an MCP server so an agent can drive the
phone with the same commands you do.

> Legal: this controls **your own device, for interoperability** (DMCA §1201(f)). It talks
> to a phone you own over a USB connection you've authorized ("Trust This Computer"). Don't
> point it at a device that isn't yours.

## Why two paths

TapKit reverse-engineers three raw-hardware mechanisms (USB CoreMediaIO screen capture,
Bluetooth-Classic HID keyboard + absolute pointer, AssistiveTouch via lockdown). None of
those is a REST API, so the [CLI Printing Press](https://github.com/mvanhorn/cli-printing-press)
(`/climaker`) — which generates a CLI+MCP from an OpenAPI/REST surface — can only wrap a path
that *has* a REST surface. That's WebDriverAgent. So this repo ships both:

| | **Path B — WebDriverAgent** | **Path A — native (no agent)** |
|---|---|---|
| Installs on the phone | WDA developer app (once, signed) | nothing |
| Transport | XCTest HTTP server (:8100) over a USB forward | CoreMediaIO (eyes) + Bluetooth-Classic HID (hands) |
| Control surface | full: tap / swipe / type / apps / open URL / element-find / source | screen capture + spec-correct HID reports |
| Generated by `/climaker` | **yes** — CLI+MCP printed from `wda-openapi.yaml` | no (raw Swift; nothing to wrap) |
| Needs | `go-ios` tunnel (sudo, iOS 17+) + Apple signing | USB + Trust |
| Default | ✅ full real injection today | fallback when nothing may touch the phone |

## Layout

```
iphonectl/
├── wda-openapi.yaml    # 28-route OpenAPI 3.0.3 spec for WebDriverAgent (input to /climaker)
├── wda/                # GENERATED Go CLI + MCP server (cli-printing-press output)
│   ├── cmd/iphonectl-pp-cli/        # Cobra CLI
│   └── build/iphonectl-pp-mcp-darwin-arm64.mcpb   # MCP bundle
├── bin/iphonectl-setup # bash orchestrator over go-ios (tunnel/install/run/forward/session)
├── native/             # Path A — Swift package, no on-device agent
│   └── Sources/iphonectl-native/{CMIOScreenCapture,BluetoothHID,HIDDescriptors,main}.swift
└── docs/
```

## Path B — WebDriverAgent (default, full control)

Prereqs: [`go-ios`](https://github.com/danielpaulus/go-ios) (`~/go/bin/go-ios`), an Apple
signing identity, and Xcode. One-time signing setup is described by `bin/iphonectl-setup help`.

```bash
cd iphonectl
./bin/iphonectl-setup tunnel      # terminal 1 — stays running, sudo (iOS 17+)
./bin/iphonectl-setup install     # first run only: sign + install WDA on the phone
./bin/iphonectl-setup up          # run WDA, forward :8100, create a session
```

Then drive it with the generated CLI (build once with
`cd wda && go build -o iphonectl-pp-cli ./cmd/iphonectl-pp-cli`):

```bash
iphonectl-pp-cli status                 # device + WDA readiness
iphonectl-pp-cli screenshot             # full-screen PNG (base64)
iphonectl-pp-cli wda device-info        # model / iOS / screen size
iphonectl-pp-cli wda homescreen         # press Home
SID=$(cat ~/.config/iphonectl/session-id)
iphonectl-pp-cli session wda "$SID" ... # tap / swipe / keys / pressButton / apps.*
iphonectl-pp-cli session url  "$SID" ... # open a deep link
```

Every command has `--json`, `--select`, `--dry-run`, `--stdin`. The MCP server at
`wda/build/iphonectl-pp-mcp-darwin-arm64.mcpb` exposes every command as an MCP tool, so an
agent gets the same surface.

## Path A — native, nothing on the phone

Swift package; `swift build`, binary at `native/.build/debug/iphonectl-native`.

```bash
iphonectl-native devices              # USB iPhones as CoreMediaIO capture devices
iphonectl-native screenshot out.png   # capture one frame (phone unlocked + screen published)
iphonectl-native hid-descriptor       # keyboard + absolute-pointer HID descriptors
iphonectl-native tap 0.5 0.5          # HID reports for a tap at normalized coords
iphonectl-native type "hello"         # HID keyboard reports for text
```

`tap`/`type` build **spec-correct** USB-HID input reports (verifiable against the HID Usage
Tables) and, by default, print the wire bytes through a `DryRun` transport so the report math
is testable with no paired device. Live injection needs a Bluetooth-Classic L2CAP transport —
the private-CoreBluetooth boundary TapKit uses (`CBClassicManager` / `CBL2CAPChannel` + HIDP);
it's documented as a pluggable `HIDTransport` in `native/Sources/iphonectl-native/BluetoothHID.swift`.

## The Claude skill

`~/.claude/skills/iphonectl/SKILL.md` routes an agent to the right backend by intent
("screenshot my phone", "tap/type/open app", "control it without installing anything"),
with the bring-up commands and per-symptom troubleshooting.

## Verified against a real device (2026-09-28)

Tested on a physical **iPhone 17 Pro** (`iPhone18,1`), **iOS 27.0**, UDID `00008150-…`,
macOS 27, Swift 6.4:

- **Live device link (Path B transport, no tunnel):** `go-ios` lockdownd query returned
  `DeviceName=iPhone, ProductType=iPhone18,1, ProductVersion=27.0, CPUArchitecture=arm64e` —
  a genuine authenticated read off the physical phone. `bin/iphonectl-setup preflight` passes.
- **Both binaries build clean:** the generated Go CLI+MCP (`go build`) and the native Swift
  tool (`swift build`); `iphonectl-native hid-descriptor` / `tap` / `type` emit correct reports.

### Known environment walls (iOS 27, honest status)

- **Path B mutating actuation (tap / launch / setlocation)** requires an active `go-ios`
  tunnel **and** a mounted Developer Image. On iOS 17+ the tunnel must run as a foreground
  `sudo` process; from a backgrounded shell the userspace agent stays at *"Waiting for
  go-ios agent to be ready"* and `image mount` fails. **Unblock:** run
  `sudo go-ios tunnel start` in its own terminal and leave it running, then `iphonectl-pp-cli`
  actuation works.
- **Path A live screen capture** depends on the phone publishing a CoreMediaIO
  screen-capture device. On this macOS 27 host a raw CMIO enumeration returns only the
  built-in and virtual cameras — iOS 27 does not expose the legacy `AllowScreenCaptureDevices`
  DAL device to an unsigned CLI. A signed helper with the camera entitlement (what TapKit
  ships) is the path to live frames.
